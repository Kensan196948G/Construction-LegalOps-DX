# AI 免責ポリシー (AI Disclaimer Policy)

本書は Construction-LegalOps-DX における AI 補助機能の利用範囲、画面表示文言、ログ保存、外部送信制御、最終判断者明示、機密情報マスキング規則を定める。AI は「法務補助者」であり「法的判断者」ではない。最終判断は法務担当者・管理部門責任者・顧問弁護士が行う。

---

## 1. 基本原則

1. **AI は補助ツール**: 条項抽出、リスクスコア試算、類似案件提示、要約、誤記検出を行う。
2. **最終判断は人間**: 契約締結可否、条項合意、損害賠償判断、訴訟方針はすべて人間。
3. **透明性**: AI 出力には常に「AI 補助結果」ラベルと「最終判断者」を表示。
4. **再現性**: 入力プロンプト・モデルバージョン・出力結果をログ保存。
5. **機密保護**: 機密情報は外部 AI（汎用 LLM API）に送信する前に必ずマスキング。
6. **教育義務**: 利用者は AI 補助機能の限界について研修を受講していなければならない。

## 2. 画面表示文言

### 2.1 共通バナー（必須表示、契約レビュー画面冒頭）

```
[本画面の表示は AI による補助結果です]
最終判断者: 法務担当者 / 法務課長 / 管理本部長 / 顧問弁護士
本結果は契約締結可否を判定するものではありません。
必ず原文・添付資料・関係法令を確認の上、人手で承認してください。
```

### 2.2 リスクスコア表示横

```
リスクスコア: XX 点 (AI 試算値)
※ スコアは社内基準による相対指標であり、法的有効性とは無関係です。
```

### 2.3 条項抽出結果

```
[AI 抽出] 抽出漏れの可能性があります。原文を必ず参照してください。
```

### 2.4 類似案件提示

```
[AI 検索] 類似性は機械的な指標です。背景・当事者・取引条件の同一性は法務担当者が判定してください。
```

### 2.5 PDF / Word エクスポート時の脚注

すべての出力ドキュメントの末尾に以下を付与：

```
本ドキュメントには AI 補助機能による生成・分析結果が含まれます。
内容の最終確認・採否は人間（法務担当者・顧問弁護士）が行っています。
出力日時: YYYY-MM-DD HH:MM JST / モデル: <model-id> / 利用者: <user-id>
```

### 2.6 顧問弁護士への共有時

外部共有用 PDF には自動で「Confidential - Attorney Work Product」スタンプを付与。

## 3. AI 利用範囲（許可・禁止）

### 3.1 許可される利用
- 契約原文の OCR・テキスト抽出。
- 条項分類・必要記載事項チェック。
- 雛形との差分検出、用語ゆらぎ正規化。
- リスクスコア試算（`risk_scoring_policy.md`）。
- 類似過去案件の検索・提示。
- 議事録・折衝メモの要約。
- 法令・通達のキーワード検索アシスト。
- 翻訳補助（英文契約の参考訳、最終確認は人間）。

### 3.2 禁止される利用
- 契約締結可否判断の自動化。
- 顧客・相手方への AI 生成文書の無確認送付。
- 訴訟方針・和解金額の決定。
- 公的機関への提出書類への AI 単独生成適用。
- 顧問弁護士助言の代替。
- 個人情報・マイナンバーを外部 AI に未マスキングで送信。

## 4. モデル・基盤の構成

### 4.1 利用モデルの区分

| 区分 | 用途 | データ取扱 |
|------|------|-----------|
| 社内 LLM（自社環境内、推論専用） | 機微情報を含む契約レビュー、リスクスコア | 入出力とも外部送信なし |
| 社内 RAG（ベクタ DB、社内 SharePoint 連携） | 過去案件検索 | 内部のみ |
| 外部 API（OpenAI / Azure OpenAI / Anthropic 等） | 機微情報を含まない要約・翻訳補助 | マスキング済データのみ |

### 4.2 外部送信制御

- 外部 API への送信は HENNGE One の DLP ポリシーで監視。
- 機密検出ルール（マイナンバー、口座、許可番号、パスポート、運転免許）に該当した場合は自動ブロック。
- 例外申請は管理本部長承認かつ監査ログ記録。
- 外部 API 利用は Entra ID 経由のサービスプリンシパルで認証、IP 制限。

### 4.3 モデル更新管理

- モデルバージョンを `model_id` として記録。
- バージョンアップ時は法務 DX 担当が回帰テスト（過去 50 案件で再採点比較）。
- 重要モデル変更は管理本部長承認。

## 5. 機密情報マスキング規則

### 5.1 マスキング対象

| カテゴリ | 例 | 処理 |
|----------|------|------|
| マイナンバー | 12 桁数字 | 全置換（`<MyNumber>`） |
| 銀行口座 | 銀行名 + 口座番号 | 番号部分を置換 |
| パスポート番号 | 英数 9 桁 | 置換 |
| 運転免許番号 | 12 桁 | 置換 |
| 個人氏名（契約代表者以外） | 自然人氏名 | 必要に応じて仮名化 |
| 住所（個人） | 自然人居所 | 都道府県・市までに丸める |
| 電話番号（個人） | 080/090 | 置換 |
| メールアドレス（個人） | gmail/yahoo 等個人 | 置換 |
| 健康情報・要配慮個人情報 | 病歴・障害等 | 削除 |
| 役員報酬・個人収入 | 額面 | 置換 |
| 入札積算根拠 | 単価・歩掛 | 外部 AI 送信禁止 |

### 5.2 マスキング処理フロー

1. アップロード時に DLP スキャナがパターン検出。
2. 検出データはトークン化（一意 ID 化）。
3. 内部処理ではトークンを保持、外部送信時はマスク表示。
4. 出力時に内部処理結果に対しトークンを復元（人間にだけ可視）。

### 5.3 マスキング失敗時の挙動

- 外部送信時に DLP が機密語句を再検出した場合、送信を中断して管理者に通知。
- 法務 DX 担当はマスキング辞書を四半期更新。

## 6. ログ保存

### 6.1 記録項目

- 入力テキスト（マスク済）、入力ファイル ID、トークン数。
- 出力テキスト、出力時刻、モデル ID、バージョン。
- 利用者 ID、ロール、所属、IP、デバイス。
- プロンプトテンプレート ID とパラメータ。
- 推論経路（社内 LLM か外部 API か）。
- 関連契約案件 ID。

### 6.2 保存期間

- 契約締結に至った案件: 契約満了 + 10 年。
- 不成立案件: 5 年。
- 訴訟関連: 訴訟終結後 10 年。

### 6.3 改ざん防止

- ログは追記型ストレージ（WORM 相当）に保管。
- ハッシュチェーンで日次完全性検証（`audit_log_policy.md` 参照）。

## 7. 利用者責務

1. AI 出力を鵜呑みにしない（特に法令解釈、判例）。
2. 機密情報を AI に投入する際はマスキング機能を使う。
3. AI 出力に依拠して相手方に意思表示する場合は、必ず人手で再確認。
4. AI の誤りを発見した場合は法務 DX 担当に報告（フィードバックループ）。
5. アカウントを他人と共有しない。

---

## 8. インシデント対応

### 8.1 想定インシデント

- 機密情報の外部 AI への意図しない送信。
- 誤った AI 出力に基づく契約締結。
- AI 出力の改ざん（内部不正）。
- モデル提供者側の脆弱性公表。

### 8.2 対応フロー

1. 検知（DLP / 監査ログ / 利用者通報）。
2. 法務 DX 担当 → 法務課長 → 管理本部長へ即時報告（30 分以内）。
3. 必要に応じて IT 部門が外部 API 接続停止。
4. 個人情報該当時は個人情報保護委員会報告判断（漏えい等該当性）。
5. 顧問弁護士助言を仰ぐ。
6. 事後レビューと再発防止策（モデル変更・教育・規程改定）。

---

## 9. 利用者教育

- 入社時・年 1 回必修。
- AI 出力の見方、マスキングの使い方、よくある誤りパターン。
- テスト合格者のみアカウント発行（HRMS 連携）。

---

## 10. 改訂

- 法令改正・モデル変更時は速やかに改訂。
- 改訂時は社内告知 + 強制再同意（次回ログイン時）。
