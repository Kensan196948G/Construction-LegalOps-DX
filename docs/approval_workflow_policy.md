# 承認ワークフロー方針 (Approval Workflow Policy)

本書は契約案件の承認ルート・エスカレーション・差戻し条件・顧問弁護士フラグ条件を定める。金額・契約種別・リスクスコアの 3 軸で承認ルートを自動決定する。AI は補助、最終承認は人間（法務担当者・管理本部長・役員・顧問弁護士）が行う。

---

## 1. 設計原則

1. 多重承認による属人化排除。
2. 起票者・承認者の分離（同一人物による起票＋承認禁止）。
3. 公共工事案件は最低 2 人法務関与（法務担当 + 課長）。
4. 一定金額以上は役員承認、戦略的重要案件は取締役会報告。
5. 顧問弁護士フラグは自動付与条件に該当した時点で外せない（外す場合は管理本部長承認 + 記録）。
6. DeskNet's Neo の稟議とは別レイヤ（法務専用フロー）として運用し、本システム承認後に稟議起票。

---

## 2. 承認ルート決定マトリクス

### 2.1 ベースルート（金額×リスク）

| 金額 / リスク | 低 (Low) | 中 (Medium) | 高 (High) | 最高 (Critical) |
|---------------|---------|-------------|-----------|-----------------|
| 〜 500 万円 | A1 | A2 | B1 | C1 |
| 〜 3,000 万円 | A2 | B1 | B2 | C1 |
| 〜 1 億円 | B1 | B2 | C1 | C2 |
| 〜 5 億円 | B2 | C1 | C2 | D1 |
| 5 億円超 | C1 | C2 | D1 | D1 |

### 2.2 ルート定義

| コード | 承認ステップ |
|--------|--------------|
| A1 | 法務担当 1 名 → 完了 |
| A2 | 法務担当 → 法務課長 → 完了 |
| B1 | 法務担当 → 法務課長 → 事業本部長 → 完了 |
| B2 | 法務担当 → 法務課長 → 管理本部長 → 完了 |
| C1 | 法務担当 → 法務課長 → 管理本部長 → 担当役員 → 完了 |
| C2 | 法務担当 → 法務課長 → 顧問弁護士確認 → 管理本部長 → 担当役員 → 完了 |
| D1 | 法務担当 → 法務課長 → 顧問弁護士確認 → 管理本部長 → 代表取締役 → 取締役会報告 → 完了 |

### 2.3 契約種別による追加要件

| 契約種別 | 追加要件 |
|----------|----------|
| 工事請負（公共） | 営業部門長承認、入札関連書類との整合確認 |
| 工事請負（民間 大口） | 信用調査結果添付 |
| 下請契約 | 施工体制台帳・社会保険加入チェック必須、購買部門承認 |
| 業務委託 | 偽装請負チェックリスト記入必須 |
| NDA（一方開示 / 当社開示側） | 法務担当のみ可 |
| NDA（当社受領側で重大情報） | 法務課長確認 |
| JV 協定 | 自動的に C2 以上、JV 構成員与信確認 |
| 変更契約書 | 原契約の承認者以上のレイヤで承認 |
| 訴訟関連（和解・訴訟提起・応訴） | 必ず D1 ルート |

## 3. 各承認者の役割

### 3.1 法務担当者
- AI 一次レビュー結果の妥当性検証。
- 条項単位での修正・差戻し。
- リスクスコアの確定（オーバーライド可、±20 点まで）。

### 3.2 法務課長
- 法務担当の判断レビュー、社内整合性確認。
- 顧問弁護士エスカレーション判断。
- 法務担当が利害関係を有する案件の代行レビュー。

### 3.3 事業本部長 / 営業部門長
- 事業戦略との整合、案件採算性判断。

### 3.4 管理本部長
- コーポレートガバナンス観点。
- 規程逸脱の承認可否。

### 3.5 担当役員 / 代表取締役
- 経営判断。
- 取締役会報告要否の決定。

### 3.6 顧問弁護士
- 高難度・新類型・係争懸念案件の助言。
- 助言は本システム外（メール / 対面）でも可、ただし結論サマリは本システムに記録。

## 4. 顧問弁護士フラグ自動付与条件

以下のいずれかに該当した場合、システムは自動的に顧問弁護士フラグを立て、外すには管理本部長承認 + 理由記録が必要。

1. リスクスコア 80 点以上。
2. 損害賠償上限なし、または契約金額の 100% 超。
3. 5 億円以上の案件。
4. 海外法準拠／外国管轄の案件。
5. 係争予兆あり（書面による損害賠償請求、解除通告、催告書受領）。
6. 反社チェックで該当または疑義あり。
7. 新類型契約（過去 24 ヶ月で同種社内事例 3 件未満）。
8. 公共工事の入札参加資格・指名停止に直結する内容。
9. 知的財産権の重要譲渡（特許出願、ソフトウェアの著作権全部譲渡で 1,000 万円超）。
10. 個人情報の越境移転（GDPR / 中国 PIPL 等該当）。

## 5. エスカレーション

### 5.1 上位エスカレーション

- 承認 SLA 超過: SLA + 1 営業日経過で次階層に自動通知。
- 承認 SLA + 3 営業日経過: 1 段階上位に承認権限委譲（代行承認）。
- 緊急案件（災害復旧等）: 起票時に「緊急」フラグ、SLA を 50% 短縮、事後監査必須。

### 5.2 横展開エスカレーション

- 同一相手方に複数案件係属時は、法務担当者を統一して一貫レビュー。
- 業界横断的重大事項（法令改正の影響大）は法務課長から全担当者に展開し、係属中案件を一括見直し。

## 6. 差戻し条件

承認者は以下のいずれかに該当した場合、起票者または前段階に差戻す。

### 6.1 必須差戻し
- 必要記載事項の欠落（建設業法 19 条、下請法 3 条、雛形必須項目）。
- 反社条項なし、または不十分。
- 当事者表示の誤記（商号・代表者・許可番号）。
- 添付書類不足（仕様書、設計図書、見積書、信用調査、JV 協定）。
- 公共工事案件で施工体制台帳未整合。
- 個人情報取扱がありながら同意・通知条項なし。

### 6.2 任意差戻し（リスクに応じ判断）
- リスクスコア 60 点超で軽減策が提示されていない。
- 過去類似案件と乖離が大きい（金額・条件）。
- 雛形バージョンが旧版。

### 6.3 差戻し時の必須記録
- 理由コード（DR-001〜DR-099、Master 参照）。
- 自由記述の理由。
- 差戻し先（起票者／前承認者）。
- 是正期限。

---

## 7. 代行・委任

- 法務担当者は休暇・出張時に代行者を事前登録。
- 役員承認は副担当役員 1 名を必ず指定。
- 代行行為もログに残し、後日本人確認を行う。

---

## 8. システム動作仕様（要約）

- 承認画面では「契約サマリ」「AI レビュー結果」「リスクスコア」「過去同種案件 5 件」を並べて表示。
- 承認ボタンは「承認」「条件付承認」「差戻し」「保留」。
- 「条件付承認」は条件文を必須入力、起票者が条件達成記録を残さない限り締結不可。
- 承認完了後の修正は新規バージョンとして起票し、再承認を必要とする。
- 承認操作は Entra ID 多要素認証セッションを要求（高リスク案件は再認証）。

|------|---------|-----------|

---

## 10. AI 補助の限界

- 承認ルート自動判定は条件マッチに基づくが、戦略的重要性・取引政策は人間判断。
- AI は承認自体は行わない。承認者の操作を促す UI に留まる。
- 顧問弁護士フラグ自動付与は安全側に倒し、不要と判断する場合は人手で解除する。
