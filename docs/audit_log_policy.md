# 監査ログポリシー (Audit Log Policy)

本書は Construction-LegalOps-DX における監査ログの設計・運用・保管・改ざん防止・エクスポート・e-文書法対応方針を定める。法務業務 SaaS の信頼性確保と訴訟対応に耐える証拠保全を目的とする。

---

## 1. 目的

1. 契約・法務業務の操作証跡を完全に記録。
2. 内部統制（J-SOX 相当）、外部監査、訴訟・行政調査への対応。
3. 不正・誤操作の早期検出。
4. AI 利用の透明性確保。
5. 個人情報保護法・電子帳簿保存法・e-文書法への適合。

---

## 2. 記録対象イベント

### 2.1 認証・アクセス
- ログイン成功・失敗（Entra ID SSO 経由 / 直接）。
- MFA 試行・失敗。
- ロール切替、代行ログイン、impersonation。
- パスワード変更、デバイス登録、HENNGE One 認証イベント。
- ログアウト、セッションタイムアウト、強制ログアウト。

### 2.2 契約レコード操作
- 案件起票、編集、削除（論理削除）、復元。
- ファイルアップロード・ダウンロード、プレビュー。
- ステータス変更（draft → review → approved 等）。
- バージョン作成、差分閲覧、ロールバック。
- 添付ドキュメントの SharePoint / DirectCloud 連携イベント。

### 2.3 承認・ワークフロー
- 承認・条件付承認・差戻し・保留。
- 顧問弁護士フラグの付与・解除。
- リスクスコアのオーバーライド。
- 緊急発議モード使用。

### 2.4 AI 利用
- AI 推論実行（モデル ID、バージョン、トークン数、所要時間）。
- 外部 API 送信可否判定（DLP 結果）。
- マスキング適用箇所件数。
- プロンプトテンプレート ID。

### 2.5 マスタ管理
- ユーザ作成・変更・無効化。
- ロール権限変更。
- 雛形マスタ・規程マスタの更新。
- リスクスコアモデル重み変更。

### 2.6 セキュリティ
- 権限拒否（403）、認可違反試行。
- レート超過、API キー使用、IP 制限違反。
- データエクスポート、CSV/PDF 出力。

### 2.7 監査人操作
- 監査ログ閲覧・検索・エクスポート（メタ監査）。

## 3. ログ項目（共通スキーマ）

| 項目 | 例 |
|------|-----|
| `event_id` | ULID |
| `timestamp` | RFC3339 ナノ秒、JST + UTC 並記 |
| `actor.user_id` | Entra ID OID |
| `actor.upn` | user@example.co.jp |
| `actor.role` | admin/legal/manager/site/auditor |
| `actor.dept` | 部署コード |
| `actor.ip` | 送信元 IP |
| `actor.device_id` | HENNGE One デバイス識別子 |
| `actor.session_id` | セッション ID |
| `action` | login / contract.update / approval.approve 等 |
| `resource.type` | contract / file / user / template |
| `resource.id` | リソース ID |
| `resource.classification` | confidential / restricted / public |
| `result` | success / failure / denied |
| `reason_code` | 失敗・差戻し理由コード |
| `diff` | 変更前後のキー単位差分（機微項目はトークン化） |
| `ai.model_id` | 該当時のみ |
| `ai.prompt_template_id` | 該当時のみ |
| `prev_hash` | 直前イベントの SHA-256 |
| `event_hash` | 当該イベントの SHA-256 |
| `signature` | KMS による署名 |

---

## 4. 改ざん防止（ハッシュチェーン）

### 4.1 仕組み

1. 各イベント書込時に直前イベントのハッシュを参照し、現在イベントのハッシュを算出。
2. `event_hash = SHA256(prev_hash || canonical_json(event))`。
3. 日次ロールアップ: 当日分の最終ハッシュを「日次アンカー」として別ストレージに保存し、Azure Key Vault (HSM 裏付け) で署名。
4. 月次アンカーをタイムスタンプ局（時刻認証局: TSA）に提出し、長期署名 (PAdES-LTA / RFC3161) を取得。
5. 検証ジョブが毎日自動実行され、チェーン途切れ・改竄を検出。

### 4.2 異常検知

- ハッシュチェーン破綻、署名検証失敗、TSA 検証失敗時は即時アラート。
- 監査ログ自体の削除・変更操作はアプリ層で禁止し、DB レベルでも追記専用（WORM 相当 + Append-only テーブル + ロールベース DBA 制限）。
- 例外的修正（プログラム不具合等）は別系統（補正イベント）として記録し、原ログは保持。

## 5. 保管期間

| 種別 | 保管期間 | 根拠 |
|------|----------|------|
| 契約締結関連監査ログ | 契約満了 + 10 年 | 民法債権消滅時効、商法、税法 |
| 訴訟・係争関連 | 終結 + 10 年 | 訴訟記録保全 |
| 不成立・解約案件 | 5 年 | 社内基準 |
| 認証・アクセスログ | 5 年 | 不正アクセス禁止法・社内 |
| 個人情報取扱ログ | 7 年 | 個人情報保護法、税法 |
| 電子取引ログ | 7 年（欠損金等 10 年） | 電子帳簿保存法 |
| AI 推論ログ | 紐付く契約と同期間 | 内部基準 |
| 監査人による閲覧ログ（メタ監査） | 10 年 | 内部統制 |

---

## 6. 保管場所

- 一次: 本システム DB の Append-only テーブル。
- 二次（即時複製）: SharePoint Online の保護ライブラリ（Microsoft 365 監査・保持ポリシー連動）。
- 三次（長期保管）: DirectCloud の WORM ストレージ。
- 四次（オフサイト）: 月次 BLOB Snapshot を地理冗長ストレージへ。
- 暗号鍵は Azure Key Vault Managed HSM。

## 7. アクセス制御

| ロール | 権限 |
|--------|------|
| auditor | 監査ログ閲覧・検索・エクスポート（読み取り専用） |
| admin (IT) | システム稼働状況・例外ログ閲覧、書き込み不可 |
| legal | 自部署関連の業務ログ閲覧（限定的） |
| その他 | 自身の操作ログのみ |

- 監査人アクセスもメタ監査の対象。
- 監査ログ表示 UI は CSV / JSONL エクスポート、検索（イベント種別、期間、ユーザ、リソース）、フィルタを提供。
- エクスポート時は透かし（利用者・出力日時）を付与。

---

## 8. エクスポート / 提出

### 8.1 標準エクスポート
- 形式: JSONL（正本） + CSV（人可読）。
- 範囲指定: 期間、ユーザ、リソース、イベント種別。
- 出力ファイルにマニフェスト（ハッシュチェーン検証手順、署名検証コマンド）を同梱。

### 8.2 法的提出（訴訟・行政調査）
- 顧問弁護士同席の上、法務課長 + 管理本部長承認。
- 第三者検証可能な形式（PDF/A-3 + 添付 JSONL + 署名）。
- 提出記録自体も監査ログ化。

### 8.3 e-文書法対応
- 電磁的記録の保存要件（真実性、可視性、検索性）に適合。
- 電子帳簿保存法のスキャナ保存要件（タイムスタンプ、解像度、入力者情報）を満たす。
- 重要書類はタイムスタンプ局による時刻認証付き。

---

## 9. アラート・モニタリング

- リアルタイムアラート対象:
  - 管理者ロールの権限変更。
  - 同一アカウントの異常な大量ダウンロード（しきい値: 1 時間 100 件以上）。
  - 顧問弁護士フラグ解除。
  - 雛形マスタ・規程マスタの更新。
  - 監査ログ整合性異常。
- 通知: Exchange Online + Teams 通知 + SOC ダッシュボード。

---

## 10. 運用

- 日次: ハッシュチェーン整合性検証、容量モニタ。
- 週次: 監査人によるサンプリングレビュー（10 件抽出）。
- 月次: TSA 時刻認証取得、保管環境のリストアテスト（四半期に 1 回フル）。
- 年次: 第三者監査受審に向けた内部監査、ポリシー見直し。

---

## 11. 廃棄

- 保管期間満了時は法務課長承認のうえ廃棄。
- 廃棄記録（誰が・いつ・どの範囲）を 10 年保管。
- 法的保留（Legal Hold）対象は保管期間を超えても廃棄しない。

---

## 12. AI 補助の限界

- 監査ログの自動分類・要約に AI を利用可能だが、判断・廃棄の決定は人間。
- ログ検索 UI で AI 自然言語検索を提供する場合も、最終的な提出範囲は人手で確認。
