## 1. はじめに

### 1.1 目的

本書は、建設業界向け法務・契約オペレーション DX プラットフォーム「Construction-LegalOps-DX」（以下、本システム）の要件を定義する。本システムは、建設業特有の長期契約・多段階下請構造・コンプライアンス要件に対応する法務・契約管理基盤を提供し、AI レビュー支援によって法務部門・契約管理部門の生産性を抜本的に向上させることを目的とする。

### 1.2 適用範囲

本書は MVP リリース（登録から 6 ヶ月後を本番リリース期限とする）に向けた機能・非機能要件を対象とする。Phase 2 以降の拡張機能はスコープ外として 9 章に列挙する。

### 1.3 用語定義

| 用語 | 定義 |
|------|------|
| 契約書 (Contract) | 当事者間で締結される法的拘束力を持つ文書 |
| 法務レビュー (Legal Review) | 契約書本文に対する法的妥当性・リスク分析の作業 |
| ワークフロー (Workflow) | 起案→法務→部長→経営層といった承認ステップの定義と実行 |
| 条項 (Clause) | 契約書を構成する個別条項単位 |
| 条項ライブラリ | 標準条項・推奨条項のマスタデータ |
| 監査ログ (Audit Log) | 改ざん防止 hash chain 付きの操作履歴 |
| Entra ID SSO | Microsoft Entra ID による OIDC ベースのシングルサインオン |
| HENNGE One | 通信経路を集約するセキュリティゲートウェイ |

## 2. ビジネス要件

### 2.1 背景

建設業界は受注高に占める契約案件数が極めて多く、JV (Joint Venture) 契約、設計委託、施工請負、下請、資材調達、賃借、許認可など契約類型が多岐にわたる。従来は紙・PDF・メール・部門共有フォルダで分散管理されており、以下の課題が顕在化している。

- 契約レビュー期間が長い（平均 5〜10 営業日）
- 標準条項からの逸脱検出が属人化している
- 監査対応時に履歴を遡れない
- 取適法（中小受託取引適正化法・旧下請法）・建設業法・独禁法・個人情報保護法の改正への追随が遅い
- リモートワークと押印フローが両立しにくい

### 2.2 ビジネスゴール

| KPI | 現状 | 目標 (6 ヶ月後) |
|-----|------|----------------|
| 平均法務レビュー期間 | 5〜10 営業日 | 2 営業日以下 |
| 標準条項逸脱の自動検出率 | 0% | 90% 以上 |
| 監査ログ網羅率 | 約 60% | 100% (改ざん検知付) |
| ユーザー満足度 (NPS) | 未計測 | +30 以上 |
| 同時接続ユーザー | — | 300 名以上 |

### 2.3 投資対効果 (ROI 想定)

法務担当 1 案件あたり平均 8 時間 → 3 時間に短縮すると仮定し、年間 1,500 案件で 7,500 時間 / 年の削減効果を見込む。

## 4. 機能要件

### 4.1 メニュー構成 (11 メニュー)

トップナビゲーションは以下 11 メニューで構成する。

1. ダッシュボード (`/dashboard`)
2. 契約管理 (`/contracts`)
3. レビュー (`/reviews`)
4. ワークフロー (`/workflows`)
5. リスク管理 (`/risks`)
6. コンプライアンス (`/compliance`)
7. テンプレート (`/templates`)
8. ナレッジ (`/knowledge`)
9. 監査ログ (`/audit-logs`)
10. レポート (`/reports`)
11. 設定 (`/settings`)

### 4.2 MVP 10 機能

MVP リリース時に必須となる機能を以下 10 件とする。

#### F-01 契約書管理 (CRUD + 版管理)

- 契約書のメタデータ (件名、相手方、契約種別、金額、期間、起案者、担当部署) を登録・更新・論理削除する
- ファイル添付 (PDF/DOCX) を SharePoint Online と連携してアップロードする
- 版管理 (version) を保持し、過去版を参照可能とする
- 検索 (全文検索 + メタデータ絞込) に対応する

#### F-02 AI 法務レビュー

- Claude API (`claude-opus-4-7` 主、`claude-sonnet-4-6` 副) を用いて契約書本文を条項単位で分析する
- 各条項について「リスクレベル (low/medium/high/critical)」「指摘事項」「修正案」「根拠条文」を提示する
- AI 出力は**参考情報**であり、最終判断は人間が行う旨の免責バナーを常設する
- レビュー結果は法務担当者が承認・却下・修正できる

#### F-03 ワークフロー / 承認フロー

- 起案 → 法務レビュー → 部長承認 → 経営層承認 → 完了 の多段ワークフロー
- 各ステップの承認者を組織マスタから選定可能
- 差戻し・並行承認・委任に対応する
- 期日超過時に通知をトリガする

#### F-04 リスク管理

- 契約全体・条項単位でリスク評価を可視化
- リスクヒートマップ (確率 × 影響度) をダッシュボードに表示
- リスク対応ステータス (未着手・対応中・受容・移転・低減・回避) を管理

#### F-05 コンプライアンスチェック

- 取適法（2026-01-01 施行・旧下請法からの新旧切替）、建設業法（19 条・労務費基準含む）、
  独禁法、個人情報保護法、暴排条項、反社チェックなどの定型チェックを実施
- チェックリストはマスタ管理しバージョニング
- 改正対応のためチェック項目の追加・改訂を画面から行う

#### F-06 テンプレート / 条項ライブラリ

- 契約書テンプレートを類型別に管理
- 推奨条項 / NG 条項 / 必須条項を条項ライブラリで一元化
- 起案時にテンプレートからの差分を自動検出

#### F-07 ナレッジマネジメント

- 過去レビュー結果、判例、社内 Q&A をナレッジとして蓄積
- 全文検索 + AI 要約による類似ナレッジ提案

#### F-08 監査ログ (改ざん防止付)

- 全 CRUD 操作・参照操作 (機密案件のみ) を記録
- 各行に SHA-256 ベースの `hash_chain` を持たせ、前行ハッシュとの連鎖で改ざんを検知
- 監査用 CSV エクスポート対応

#### F-09 SSO 認証 / 認可

- Entra ID OIDC による SSO ログイン (HENNGE One 経由)
- ロール: viewer / drafter / reviewer / approver / admin / auditor / guest
- 部署属性・案件機密度に応じた行レベルアクセス制御

#### F-10 通知・連携

- メール (Exchange Online) / Microsoft Teams / DeskNet's Neo スケジュール連携
- 期日アラート、承認依頼、差戻し、AI レビュー完了の通知

### 4.3 業務シナリオ例

```
[営業] 案件起案 → 契約書 PDF アップロード
         ↓
[システム] AI レビュー自動実行 (Claude API)
         ↓
[法務] AI 結果を確認、追加コメント、修正提案
         ↓
[起案者] 修正対応 (相手方への提示)
         ↓
[部長] 承認 → [経営層] 承認 → 締結
         ↓
[システム] 監査ログに hash_chain 付きで全工程を記録
```

## 5. 非機能要件

### 5.1 性能 (Performance)

| 指標 | 目標値 |
|------|--------|
| 画面表示 (一覧、p95) | 1.5 秒以内 |
| 画面表示 (詳細、p95) | 2.0 秒以内 |
| AI レビュー応答 (1 契約、20 条項想定) | 平均 90 秒、最大 180 秒 |
| 同時接続ユーザー数 | 300 名 |
| ピーク時 RPS | 50 req/s |
| 検索クエリ (全文検索) | p95 1.0 秒 |

### 5.2 可用性 (Availability)

- 稼働時間: 平日 7:00 〜 22:00 (JST)
- 計画停止を除く可用性: 99.5% / 月
- バックアップ: 日次フルバックアップ + 1 時間毎の WAL アーカイブ、保存 30 日
- 災害対策: RPO 1 時間 / RTO 4 時間

### 5.3 セキュリティ (Security)

- 通信暗号化: TLS 1.3 必須
- 保存時暗号化: PostgreSQL は TDE 相当 (LUKS / Cloud KMS)、ファイルは SharePoint Online の暗号化に準拠
- 認証: Entra ID SSO (HENNGE One ゲートウェイ経由、IP 制限)
- 多要素認証: Entra ID の MFA を必須
- 認可: RBAC + 行レベルアクセス制御 (RLS)
- 監査ログ: 改ざん防止 hash chain、外部 SIEM (要件として Microsoft Sentinel 想定) への転送
- 脆弱性対策: 依存ライブラリの SCA を CI で実行、Critical/High は 7 日以内に対応
- 個人情報保護: 個人情報項目は別テーブルに分離、アクセスログ必須

### 5.4 ユーザビリティ (Usability)

- WCAG 2.1 AA 準拠
- 日本語 / 英語の i18n 対応 (MVP は日本語のみ)
- レスポンシブ (1280 / 1920 を主、タブレットを副でサポート)
- AI 出力に対する**免責バナー常設**

### 5.5 拡張性 / 保守性

- マイクロサービス志向のモジュラーモノリス (FastAPI + ドメイン分割)
- DB マイグレーションは Alembic に統一
- API は OpenAPI で自動生成し、`/docs` で公開 (内部のみ)
- 設定値は環境変数 + 12factor

### 5.6 運用性

- ログ: 構造化ログ (JSON) を標準出力 → Fluent Bit → 集約基盤
- メトリクス: Prometheus / Grafana を想定
- ヘルスチェック: `/healthz` (liveness), `/readyz` (readiness)
- CI/CD: GitHub Actions + Docker イメージ署名

### 5.7 法規制 / 内部統制

- 電子帳簿保存法 (令和 5 年改正対応)
- 個人情報保護法
- 取適法（中小受託取引適正化法・旧下請法）・建設業法
- J-SOX (内部統制) ：監査証跡として hash chain を活用
- 6 ヶ月後のリリース時点で法務部門による法規制レビュー完了を必須とする

- MVP 10 機能がすべて疎通し、シナリオテスト 50 件中 45 件以上が合格
- 性能要件 (p95) を満たすことを負荷試験で証明

- 監査ログの hash chain 検証コマンドで全件 OK
- 法務部門による法規制レビュー完了

## 11. 用語集 (補遺)

- **JV (Joint Venture)**: 建設業における共同企業体
- **取適法**: 中小受託取引適正化法（旧: 下請代金支払遅延等防止法。2026-01-01 施行）
- **建設業法**: 建設業の許可・契約・施工体制を規律する法律
- **OIDC**: OpenID Connect。OAuth 2.0 拡張の認証プロトコル
- **RLS**: Row Level Security。行レベルアクセス制御
- **SCA**: Software Composition Analysis。OSS 依存性スキャン
