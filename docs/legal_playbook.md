# 法務業務全体プレイブック (Legal Playbook)

本書は Construction-LegalOps-DX における法務業務の正本プレイブックである。日本の建設土木業（公共工事 8 割／民間 2 割、従業員 600 名、IT 部門 7 名）の現場〜役員〜顧問弁護士までの一貫したワークフローと、AI 法務補助機能の境界線を定義する。

---

## 1. 目的と基本方針

### 1.1 目的

- 契約・法務業務のばらつきを排除し、全社一律の品質基準を確立する。
- 公共工事を中心とした建設業特有のリスク（建設業法、下請法、入札関連法令、共同企業体協定、施工体制台帳）を制度面から統制する。
- AI による契約レビュー補助・条項抽出・リスクスコア算出を「補助者」として位置付け、最終判断は人間が担う。
- 6 ヶ月以内に本番リリースする SaaS の運用ポリシーを明文化する。

### 1.2 基本方針

1. AI は「法的判断者」ではなく「法務補助者」である。最終判断者は法務担当者・管理部門責任者・顧問弁護士のいずれかとする。
2. 全契約は本システムを通過させ、紙・メール添付のみの締結は禁止する（DirectCloud / SharePoint Online を正本格納庫とする）。
3. 既存 IT 基盤 (Entra ID, HENNGE One, M365, SharePoint Online, Exchange Online, DeskNet's Neo, DirectCloud) と整合する形で構築し、二重認証・通信統制・ログ集約を維持する。
4. 公共工事に関わる契約は、入札参加資格・経営事項審査・施工体制台帳と整合させる。
5. 法務ノウハウは Memory（長期知識）と SharePoint の参照文書に分離し、機微情報は外部 AI に送信しない。

## 2. 組織体制と役割分担

### 2.1 組織図（法務関与レイヤ）

```
[ 顧問弁護士 (外部) ]
        ▲
        │ 高難度・訴訟リスク・新類型契約
        │
[ 役員 (取締役会・常務会) ]
        ▲
        │ 一定金額超・重要契約・係争懸念
        │
[ 管理本部 法務課 ]
        ▲
        │ 契約審査・規程整備・教育
        │
[ 本社 各事業本部 ]── 営業 / 工事 / 購買 / 安全
        ▲
        │ 一次審査・社内回付
        │
[ 支店 (北海道〜九州 計 12 支店) ]
        ▲
        │ 現場発議・支店長承認
        │
[ 現場事務所 (作業所長) ]
```

### 2.2 役割マトリクス

| 主体 | 主な役割 | 本システム上の権限 |
|------|----------|-------------------|
| 作業所長 / 現場事務 | 契約原案発議、相手方ドラフト受領、添付資料収集 | role=site (起票・コメント・自社情報閲覧) |
| 支店長 / 支店総務 | 一次承認、支店内予算判断、地場業者対応 | role=manager (支店配下の案件承認) |
| 本社事業本部 | 事業横断調整、共同企業体 (JV) 案件統合 | role=manager (本部配下案件) |
| 法務課 (専任 5 名) | 契約審査、リスクスコア確定、条項修正、AI 補助結果の最終判断 | role=legal (全社閲覧・編集・差戻し) |
| 管理本部長 | 規程改定承認、年度方針、顧問弁護士エスカレーション可否 | role=admin |
| 役員 | 一定金額超／重要案件の最終承認、係争・和解判断 | role=admin (承認専用 UI) |
| 顧問弁護士 (外部 2 法律事務所) | 高難度案件助言、訴訟代理、重要新類型契約レビュー | 外部参加。SharePoint 限定共有 + HENNGE One 経由メール |
| 内部監査室 | 監査ログ確認、規程準拠性チェック | role=auditor (読み取り + 監査ログ抽出専用) |
| IT 部門 (7 名) | システム運用、Entra ID/HENNGE One 連携、ログ基盤 | role=admin (システム管理ロール) |

### 2.3 法務課の体制

- 法務課長 1 名（弁護士有資格者ではなくとも可、ただし顧問弁護士と直接窓口）
- 契約審査担当 2 名（建設業法・下請法に精通）
- 訴訟・債権担当 1 名
- コンプライアンス担当 1 名（反社・贈収賄・談合対策）
- 法務 DX 担当（IT 部門との兼務 1 名、本システムのプロダクトオーナー役）

## 3. 契約ライフサイクル

### 3.1 ステージ定義

```
[1.発議] → [2.原案作成] → [3.AI 一次レビュー] → [4.法務審査]
   → [5.相手方折衝] → [6.最終ドラフト確定] → [7.稟議・承認]
   → [8.締結 (電子/紙)] → [9.保管・正本化]
   → [10.履行監視] → [11.変更管理] → [12.終了/更新/解除]
```

### 3.2 各ステージの責務

#### 1. 発議
- 起票者: 現場事務所または営業担当。
- 必須項目: 案件名、相手方、契約種別、想定金額、工期、公共／民間区分、JV 区分、再委託有無。
- システム動作: state=draft、案件 ID 採番、SharePoint フォルダ自動生成。

#### 2. 原案作成
- 自社雛形 (工事請負／下請／NDA／業務委託／覚書／発注書／協定書／変更契約書) を本システムから呼び出し。
- 相手方ドラフトの場合は PDF/Word を取込、テキスト抽出。

#### 3. AI 一次レビュー
- 条項抽出、欠落条項チェック、リスクスコア試算、類似過去案件提示。
- 出力には必ず「AI 補助結果。最終判断者は法務担当者です。」の表示を付す（`ai_disclaimer_policy.md` 参照）。
- 公共工事案件は AI 出力に「公共工事チェックリスト未確認」フラグを必ず付与する。

#### 4. 法務審査
- 法務担当者は AI 結果と原文を突合し、条項単位で承認／修正／差戻し。
- 差戻し時は理由コードを必須入力（`approval_workflow_policy.md` 参照）。

#### 5. 相手方折衝
- 修正案を相手方に送付 (Exchange Online 経由、HENNGE One ポリシー適用)。
- 折衝記録は本システムにスレッド形式で残す。

#### 6. 最終ドラフト確定
- バージョン番号 (v1.0, v1.1...) と差分ハイライトを保存。
- AI による「最終差分の再スコアリング」を実施。

#### 7. 稟議・承認
- DeskNet's Neo の稟議とは別に、本システム内で法務専用ワークフローを完了。
- 金額・リスク別ルート (`approval_workflow_policy.md` 参照)。

#### 8. 締結
- 電子契約: クラウドサイン等の外部サービスと API 連携（将来拡張）。当面は PDF + 電子印鑑 + メール往復を正本とする。
- 紙: 押印後にスキャンし PDF を SharePoint Online に格納、本システムから ID 紐付け。

#### 9. 保管・正本化
- 正本: DirectCloud (長期保管・冗長化)。
- 副本: SharePoint Online（業務利用）。
- メタデータ: 本システム DB に保管（契約期間、自動更新有無、解除条件サマリ）。

#### 10. 履行監視
- 期限通知（更新日 60／30／14／7 日前）。
- 下請契約は施工体制台帳・労務安全書類との整合チェックを定期実行。

#### 11. 変更管理
- 変更契約書テンプレートで起票。原契約 ID を必須リンク。
- 金額増減・工期延長は AI が自動で「主要変更点」要約を生成。

#### 12. 終了・更新・解除
- 終了時はチェックリストに従い、瑕疵担保（契約不適合責任）期間管理に移行。
- 解除は顧問弁護士フラグ自動付与。

## 4. AI 補助の境界線

### 4.1 AI が担う範囲（補助）

- 条項抽出、欠落条項チェック、用語ゆらぎ正規化。
- 雛形との差分検出、リスクスコア試算、類似案件提示。
- 用語解説、関連法令の参照リンク提示。
- 議事録・折衝メモの要約。

### 4.2 AI が担わない範囲（人間判断）

- 条項の最終可否判断。
- 損害賠償上限・契約不適合期間など重要条件の決定。
- 相手方への意思表示（合意・解除・損害賠償請求等）。
- 訴訟方針、和解金額、和解可否。
- 公共工事の入札辞退・指名停止対応。

### 4.3 AI 結果の取扱い原則

1. AI 結果は必ず「補助」ラベル付きで表示する。
2. AI 出力をそのまま顧客・相手方に転送することを禁止する。
3. AI に投入するデータは事前にマスキング規則 (`ai_disclaimer_policy.md`) に従う。
4. AI 出力ログは監査対象とし、改ざん防止ハッシュチェーンを付す。

## 5. 教育・運用定着

### 5.1 研修

- 全社向け: 年 1 回、契約発議の正しい流れと禁則事項。
- 現場向け: 工事請負・下請契約の重要条項解説（建設業法 19 条、下請法 3 条書面）。
- 法務課向け: AI 補助機能の操作研修、四半期ごとの新法令アップデート。

### 5.2 KPI

- 契約レビュー平均所要時間（目標: 営業日 2.0 日以内）。
- AI 一次レビュー利用率（目標: 全契約の 95% 以上）。
- 差戻し率（目標: 15% 以下）。
- 顧問弁護士エスカレーション率（参考: 5〜8%）。
- 期限切れ・未更新契約検出件数。

### 5.3 改善サイクル

- 月次: 法務課レビュー会で AI 出力の品質を抽出評価。
- 四半期: 規程改定提案、雛形バージョンアップ。
- 半期: 顧問弁護士同席のレビュー会で重大事例の振り返り。

## 6. 例外・緊急対応

- 災害復旧工事等で即日締結が必要な場合は「緊急発議」モードを利用。事後審査必須。
- 公共発注者からの仕様変更指示は、口頭でも記録化し、後追いで変更契約を必ず締結する。
- 重大係争予兆（書面による損害賠償請求受領等）は 24 時間以内に法務課長 → 管理本部長 → 顧問弁護士の順で連絡する。
