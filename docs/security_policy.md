# セキュリティポリシー (Security Policy)

本書は Construction-LegalOps-DX のセキュリティ統制を定める。Entra ID SSO、HENNGE One、Microsoft 365、SharePoint Online、Exchange Online、DeskNet's Neo、DirectCloud の既存環境に整合し、RBAC、部署単位閲覧制限、暗号化、機密検出、インシデント対応を体系化する。従業員 600 名、IT 部門 7 名、公共工事 8 割／民間 2 割の業態を前提とする。

---

## 1. 全体方針

1. **ゼロトラスト**: ネットワーク位置に依存せず常時検証。
2. **最小権限**: ロール・属性・案件単位で必要最小権限。
3. **多層防御**: ID、デバイス、ネットワーク、アプリケーション、データの各レイヤで防御。
4. **データ中心**: 機密度に応じた暗号化・ラベリング・DLP。
5. **継続監査**: 全操作ログ化、SOC 連携、月次レビュー。
6. **法令適合**: 個人情報保護法、サイバーセキュリティ基本法、不正アクセス禁止法、刑法、独禁法等への適合。
7. **業界適合**: 公共工事発注者からの情報セキュリティ要求事項（NISC、地方自治体）を満たす。

---

## 2. ID 管理と認証

### 2.1 Entra ID SSO
- すべてのユーザ認証は Entra ID 経由（OIDC / OAuth 2.0）。
- ローカルアカウント禁止（緊急用 break-glass 2 名のみ Vault 厳重管理）。
- グループ ベース アクセス（Entra ID セキュリティグループに RBAC を紐付け）。

### 2.2 多要素認証 (MFA)
- 全ユーザ MFA 必須（Microsoft Authenticator または FIDO2）。
- 高リスク操作（承認、データエクスポート、管理操作）は再認証（Step-up）。

### 2.3 条件付きアクセス
- デバイスコンプライアンス（Intune / HENNGE One Device Cert）必須。
- 不明な場所・匿名プロキシ・トラベル不可なジオロケーションをブロック。
- 業務時間外の管理操作には追加承認。

### 2.4 HENNGE One
- メール経路の DLP・暗号化・送信時パスワード管理。
- 外部送信時に PPAP の代替として ZIP+S/MIME またはリンク共有を利用。
- 外部 AI API への通信もポリシー対象。

### 2.5 アカウントライフサイクル
- HRMS と連携し入退社・異動を 24 時間以内に反映。
- 退職時即時無効化（Entra ID disable）、本システム上のセッション強制終了。
- 90 日無利用アカウントは自動無効化。

## 3. RBAC（ロールベース アクセス制御）

### 3.1 ロール定義

| ロール | 主用途 | 主要権限 |
|--------|--------|---------|
| `admin` | システム全体管理、IT 部門 | ユーザ・ロール管理、システム設定、監査ログ閲覧（書込不可） |
| `legal` | 法務課 | 全契約閲覧、編集、承認、AI 機能フル利用、雛形管理 |
| `manager` | 支店長・本部長・事業部門長 | 配下案件の承認、配下ユーザ案件閲覧、自部署統計 |
| `site` | 現場・営業 | 自身が起票・関与する案件のみ、起票・コメント、限定閲覧 |
| `auditor` | 内部監査室 | 全案件のメタデータ閲覧、監査ログ閲覧・エクスポート、編集・承認不可 |

### 3.2 ロール付与原則

- ロール付与は Entra ID グループ経由（直接ユーザ付与禁止）。
- `admin` は IT 部門 + 法務 DX 担当に限定（最大 8 名）。
- 兼務時は最小権限を優先（自動的に高権限ロールが付くことを避ける）。
- ロール変更は管理本部長承認、四半期レビュー。

### 3.3 属性ベース追加制御 (ABAC)

- 部署属性（支店コード、事業本部コード）でフィルタ。
- プロジェクトコード単位の ACL。
- 機密度ラベル（Public / Internal / Confidential / Restricted）で表示・編集可否を制御。

---

## 4. 部署単位閲覧制限

### 4.1 既定可視性
- 案件は起票部署 + 上位本部 + 法務課 + 担当役員 + 監査人 に閲覧可。
- 他部署案件は既定で不可視。

### 4.2 例外可視性付与
- 共同事業・JV: 構成事業部本部にも自動付与。
- 過去類似案件検索: AI が他部署案件を提示する場合はメタデータのみ表示し、本文閲覧は所属部署からの依頼経由とする。

### 4.3 機密案件
- 「Restricted」ラベル案件は明示的に登録された関係者のみ閲覧（manager ロールでも自動付与なし）。
- M&A、訴訟、人事関連の契約は原則 Restricted。

---

## 5. データ分類とラベリング

### 5.1 分類

| ラベル | 例 | 取扱 |
|--------|-----|------|
| Public | 公開済プレスリリース | 制限なし |
| Internal | 社内一般文書 | 社員のみ |
| Confidential | 標準契約書、見積 | 関係者のみ、外部送信は承認・暗号化 |
| Restricted | M&A、訴訟、賠償、個人情報・マイナンバー | 限定関係者のみ、外部送信原則禁止 |

### 5.2 ラベリング運用
- Microsoft Purview Information Protection (MIP) ラベルと連動。
- アップロード時にラベル付与を必須。AI による初期サジェスト + 人手確定。
- ラベルダウングレードは法務課長承認。

---

## 6. 暗号化

### 6.1 保存時暗号化（at rest）
- DB: TDE + 列レベル暗号化（個人情報・契約金額・条項本文）。
- ファイル: SharePoint Online / DirectCloud の暗号化機能 + アプリ層追加暗号化。
- 鍵管理: Azure Key Vault Managed HSM、年次ローテーション、緊急ローテーション手順整備。

### 6.2 通信時暗号化（in transit）
- TLS 1.2 以上必須、推奨 1.3。
- 弱い暗号スイート禁止。
- 内部間通信も mTLS。

### 6.3 端末暗号化
- ノート PC は BitLocker、スマホ・タブレットは MDM による暗号化必須。

### 6.4 バックアップ暗号化
- スナップショット・バックアップ・アーカイブも暗号化。

---

## 7. 機密検出と DLP

### 7.1 検出対象
- マイナンバー（12 桁、チェックデジット検証）。
- 銀行口座（金融機関コード + 支店 + 口座番号）。
- パスポート番号、運転免許番号、健康保険証番号。
- クレジットカード（Luhn 検証）。
- 個人氏名・住所・電話・メール（要配慮個人情報を含む文書はラベル上昇）。
- 自社建設業許可番号、入札参加資格者番号、経審点数。
- 公共発注機関内部資料の特徴語句。

### 7.2 検出ポイント
- アップロード時、保存時、外部送信時、AI 推論時、エクスポート時。
- HENNGE One DLP と本システム DLP を二重化。

### 7.3 対応
- マイナンバー検出: 原則ブロック、許可フローは法務課長 + 管理本部長承認。
- その他 PII: ラベル自動付与 + 通知。
- 検出履歴はすべて監査ログ。

## 8. アプリケーション セキュリティ

### 8.1 開発・運用
- セキュア コーディング規約（OWASP ASVS L2 相当）。
- CI に SAST / SCA / IaC スキャン。
- リリース前に DAST 実施。
- 依存パッケージは脆弱性スキャン + SBOM 管理。
- 本番への直接アクセスは踏み台 + Just-in-Time + 承認制。
- 本番デプロイは Blue/Green、ロールバック手順を文書化。

### 8.2 API
- すべての API は OIDC アクセストークン必須。
- レートリミット、CSRF / XSS 対策、入力検証。
- API キーは Vault 管理、平文保存禁止。

### 8.3 ファイル取扱
- アップロードファイルはマルウェアスキャン（Microsoft Defender 連携）。
- ファイルタイプホワイトリスト（PDF, DOCX, XLSX, JPG, PNG, ZIP（パスワード付除外））。

### 8.4 ログ・モニタ
- アプリケーション・インフラ・ネットワークの 3 層ログを SIEM 集約。
- SOC 24/7 監視（外部委託または社内 IT + MSSP）。

---

## 9. ネットワーク

- 本番環境は VNet 分離、Private Endpoint 経由。
- 管理 UI は Conditional Access + 社内 IP / Zero Trust Network Access のみ。
- 外部 AI API への送信は専用 NAT、HENNGE One DLP 連携。
- WAF + DDoS Protection を本番に適用。

---

## 10. デバイス管理

- 業務 PC は Intune 管理（または HENNGE One Device Cert）。
- BYOD は原則禁止、特例は法務 + IT 共同承認 + MDM 必須。
- USB / 外部メディアは原則ブロック。
- 紛失時は遠隔ワイプ、本システムからの強制ログアウト。

---

## 11. 第三者リスク

- ベンダー契約に秘密保持・監査権・再委託承諾・サブプロセッサ一覧開示。
- 重要ベンダー（クラウド、AI モデル提供者）は年次セキュリティアセスメント。
- サードパーティアクセスは時間制限付き + MFA。

---

## 12. インシデント対応

### 12.1 体制
- CSIRT: IT 部門長 + 法務課長 + 管理本部長 + 必要に応じ顧問弁護士。
- 24/7 窓口（メール + 電話 + Teams チャネル）。

### 12.2 フロー
1. 検知（SIEM / DLP / 利用者通報）。
2. トリアージ（30 分以内に初動）。
3. 封じ込め（アカウント無効化、ネットワーク遮断）。
4. 根本原因分析。
5. 法的判断（個人情報漏えい等の報告要否、警察通報、行政報告、相手方通知）。
6. 復旧・恒久対策。
7. 事後報告（取締役会報告）。

### 12.3 訓練
- 年 2 回の机上演習、年 1 回の実機演習。
- フィッシング訓練を四半期実施。

---

## 13. 事業継続 (BCP) / 災害対策

- RPO: 24 時間以内、RTO: 4 時間以内。
- 地理冗長バックアップ（東日本 + 西日本）。
- 年次 DR 訓練（フェイルオーバー実機）。
- 業務継続計画は災害復旧工事対応とも整合。

---

## 14. 法令適合

- 個人情報保護法、マイナンバー法、不正アクセス禁止法、サイバーセキュリティ基本法。
- 公共工事関連: NISC ガイドライン、各自治体情報セキュリティ要求事項。
- 業界: 日本建設業連合会セキュリティガイドライン。

---

## 15. AI 補助の限界

- AI で異常検知・自然言語ログ検索を補助するが、セキュリティ判定の最終責任は CSIRT。
- AI 推論経路自体もセキュリティ統制の対象。
