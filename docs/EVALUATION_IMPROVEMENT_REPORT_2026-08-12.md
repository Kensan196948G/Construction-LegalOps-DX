### 2.1 プロジェクト概要

- **目的**: 従業員約 600 名（IT・DX 7 名、公共工事 80% / 民間 20%）の建設会社で、契約レビュー・取適法/建設業法コンプライアンス・承認フロー・監査を DX する社内基盤

### 5.2 独自優位性

- 建設業法（19 条・労務費基準）・取適法（2026 施行・新旧切替）・公共工事 50 日支払・変更契約失権警告・協力会社 CCUS 等、**建設業法務の正本機能**は競合 CLM に存在しない。
- RLS + 案件 ACL + 倫理壁 + 監査ハッシュチェーン + WORM + Legal Hold の統制は、日本の法務 DX 基盤として高い独自性。
- 既存環境（Entra ID / HENNGE One / SharePoint / Exchange / desknet's NEO）との統合を前提とした社内基盤である点。

### 6.3 AI 設計方針（本セッション反映含む）

- **目的化しない**: チャット追加が目的ではなく、時間削減・検索・判断支援・説明可能性で評価する。
- **AI 不要領域**: 期限計算・支払日計算・CCUS 確認はルール/DB で実装し AI に依存しない。
- **RAG**: 一次情報コーパス（国・自治体・公的機関）+ 許可ホスト検証 + 引用 URL 検証。本セッションで法務相談を RAG 検索 UI に置換。
- **構造化抽出**: 契約書条項抽出・法令適用判定はルール + LLM のハイブリッド。
- **分類/予測/異常検知**: リスク分類は LLM+スコアリング、金額・期限異常は統計ルールから開始。
- **モデル構成**: Claude（レビュー/要約）+ Perplexity（Web 根拠調査）のハイブリッド、キーは Fernet 暗号化保存。
- **根拠・引用・信頼度**: 出力に根拠条文・一次情報 URL・source_verified を表示。
- **人間承認**: 法的判断は法務担当者・顧問弁護士、AI は下書き限定（全画面免責）。
- **権限制御**: 機密契約のマスキング + 案件 ACL を AI 入力前に適用。
- **プロンプトインジェクション**: 文書由来入力を隔離・マスキングし、システムプロンプトを固定。
- **個人・機密保護**: 機微検出 + マスキング + 保存期間ポリシー + 外部送信境界。
- **監査**: モデル・プロンプト・入出力を監査ログ化し、WORM 出力対象とする。
- **誤判定時の責任分界**: AI 免責ポリシー + 人間承認 + 監査証跡で明確化。
- **利用量・予算上限**: 接続テスト・保存キー方式は実装済み。用量上限・停止手段は本番運用計画（#23 後）で設定。
